# Guide Watcher v2 — Design Spec

## Overview

Rebuild the Auto Study Guide Generator from Python/tkinter to Tauri (Rust + Svelte) for Sublime Text-level responsiveness and Raycast/Figma-level aesthetics. The app watches for new lecture files, prompts the user, runs Claude Code in the background, and streams live output — all from the system tray.

## Tech Stack

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| Backend/Runtime | Rust via Tauri v2 | Near-native performance, ~5MB binary, <30MB RAM, native system tray |
| Frontend | Svelte 5 | Compiles to vanilla JS — no virtual DOM, minimal runtime overhead |
| Styling | Tailwind CSS 4 | Utility-first, design tokens for the custom dark theme |
| Build | Vite | Fast HMR during dev, optimized production builds |
| File Watching | `notify` crate (Rust) | Cross-platform, event-driven, same concept as Python watchdog |
| Process Management | `tokio::process` | Async stdout streaming from Claude CLI |
| Notifications | `tauri-plugin-notification` | Windows toast notifications on job completion |

## Architecture

### Backend (Rust)

#### `config.rs` — Configuration

```rust
// All paths are absolute — no placeholders, no relative resolution.
pub const WATCH_DIR: &str = "C:/Users/you/Documents/Study/4th Semester";
pub const DGIST_ROOT: &str = "C:/Users/you/Documents/Study";
pub const TEMPLATE_FILE: &str = "C:/Users/you/Documents/Study/4th Semester/_automation/guide_prompt.txt";
pub const GIT_BASH: &str = "C:/Program Files/Git/bin/bash.exe";

pub const WATCHED_EXTENSIONS: &[&str] = &[".pdf", ".html"];
pub const SKIP_FOLDERS: &[&str] = &[
    "_automation", "__MACOSX", ".ipynb_checkpoints", ".claude",
    ".vscode", "Archive-ugrp", "kisub kim", "output", "datalab",
];
pub const SKIP_PATTERNS: &[&str] = &["libgen.li", "syllabus", "guideline"];

pub const BATCH_WINDOW_SECS: u64 = 3;
pub const COOLDOWN_SECS: u64 = 60;
pub const FILE_STABILITY_TIMEOUT_SECS: u64 = 20;   // max wait for copy to finish
pub const FILE_STABILITY_POLL_MS: u64 = 1000;       // poll interval
pub const DIR_SCAN_DELAY_MS: u64 = 1500;            // wait before scanning new directories

pub const DEFAULT_MODEL: &str = "opus";
pub const DEFAULT_EFFORT: &str = "max";
pub const MODELS: &[&str] = &["opus", "sonnet", "haiku"];
pub const EFFORTS: &[&str] = &["max", "high", "medium", "low"];
```

#### `watcher.rs` — File Watching

- Uses `notify` crate with `RecommendedWatcher`
- Watches `WATCH_DIR` recursively
- On file create/move:
  - Filters by extension (`.pdf`, `.html`)
  - Skips files matching `SKIP_FOLDERS` (any path component) and `SKIP_PATTERNS` (filename substring, case-insensitive)
  - Checks cooldown (60s per file path)
  - **File stability wait**: polls file size every 1s up to 20s max. Proceeds if size stabilizes (same value twice in a row and > 0) OR if timeout expires and file still exists (fallback — proceed anyway).
  - On directory create/move: waits 1.5s (`DIR_SCAN_DELAY_MS`) via `tokio::time::sleep` to let the OS finish writing, then recursively scans for matching files. This delay is required for zip extraction scenarios where the OS creates the directory before populating files inside it.
- Batches detected files for `BATCH_WINDOW` (3s) then emits `new-files` event to frontend
- Runs on a dedicated Tokio task (not the main thread)
- File stability checks run concurrently per-file (spawned as separate tasks), not blocking the watcher

#### `claude.rs` — Claude Process Management

**Job ID**: Generated by Rust as a UUID v4 string (via `uuid` crate). Returned from `approve_files`/`start_job` commands. Threaded through all events (`job-started`, `job-output`, `job-done`) so the frontend can route events to the correct job when multiple jobs run concurrently.

**Prompt construction** — per-extension variants:

For `.pdf` files:
```
Then extract text from the PDF at '<file_path>' using pymupdf (fitz) via the Bash tool —
the Read tool cannot render PDFs on this Windows machine.
```

For `.html` files:
```
Then extract content from the HTML lecture at '<file_path>' using the regex extraction method
described in the template (JS template literals, not BeautifulSoup — the content is in
JavaScript const slides = [...] with template literals, not in the DOM).
```

For other extensions (fallback):
```
Then read the lecture file at '<file_path>' using the Read tool.
```

Full prompt template:
```
Read the study guide generation instructions from '<TEMPLATE_FILE>' using the Read tool.
<per-extension read instruction>
Follow every instruction in that template to create a comprehensive study guide.
Also check for textbook PDFs in '<output_dir>' (filenames containing 'libgen.li' are textbooks)
and weave relevant textbook content into the guide as described in the template.
You have access to the full DGIST folder at '<DGIST_ROOT>' including all semesters —
if prior course material is relevant, you may reference it.
Save the guide as '<output_name>' in '<output_dir>'.
```

**Shell script** — written to a temp file:
```bash
#!/bin/bash
cd "<output_dir>"
claude -p --verbose --output-format stream-json --model <model> --effort <effort> \
  --dangerously-skip-permissions --add-dir "<DGIST_ROOT>" <<'GUIDEPROMPT'
<prompt>
GUIDEPROMPT
```

**Why `--login` is required**: The `--login` flag causes Git Bash to source `/etc/profile` and `~/.bash_profile`, which is what puts `claude` (installed as a global npm package) onto `PATH`. Without this flag, `claude` will not be found and the job will fail silently. This flag must never be removed.

**Spawning**:
- `tokio::process::Command::new(GIT_BASH).args(["--login", &sh_path])`
- Windows: `CREATE_NO_WINDOW` creation flag (no visible terminal)
- `stdout(Stdio::piped())`, `stderr(Stdio::inherit())` — stderr goes to Rust's stderr for debugging
- Reads stdout via `BufReader::new(child.stdout).lines()` in an async loop

**Events emitted** (all carry `job_id: String`):

- `job-started { job_id }` — immediately after process spawns
- `job-output { job_id, line: String }` — for each stdout line (raw, unparsed — frontend parses)
- `job-done { job_id, exit_code: i32, output_file_exists: bool }` — after process exits

**Parsing responsibility**: `claude.rs` forwards raw stdout lines to the frontend. All JSON parsing happens in `src/lib/parser.js` (single source of truth). This avoids duplicated parsing logic between Rust and JS.

**Error handling**:
- If `GIT_BASH` path does not exist: emit `job-done { job_id, exit_code: -1, output_file_exists: false }` and emit a `job-output` line with `"Error: Git Bash not found at <path>. Install Git for Windows."` so the error appears in the log panel.
- If the temp `.sh` file cannot be written: same pattern — emit error via `job-output`, then `job-done` with failure.
- If the process crashes mid-run: the async stdout loop exits, process exit code is captured, `job-done` emitted normally.

#### `main.rs` — App Entry & System Tray

**Startup validation** (runs before Tauri app launches):
1. Check `TEMPLATE_FILE` exists → if not, show a native error dialog via `tauri-plugin-dialog` and exit
2. Check `GIT_BASH` exists → if not, show error dialog and exit
3. Check `WATCH_DIR` exists → if not, show error dialog and exit

**Tauri app setup**:
- Single window, `visible: false` on startup (starts hidden in tray)
- System tray icon with menu: "Show Window" (default/double-click), separator, "Quit"
- Window close (X button) → `event.prevent_close()` + hide window (not quit)

**IPC commands**:
- `approve_files(file_paths: Vec<String>, model: String, effort: String) -> Vec<String>` — starts a job for each file path, returns a `Vec` of generated `job_id` UUIDs. This is the command `ConfirmPanel.svelte` invokes. Single model/effort applies to all files in the batch (intentional — matches the single-selector UI).
- `start_job(file_path: String, model: String, effort: String) -> String` — starts a single job, returns `job_id`. Available for programmatic use but `ConfirmPanel` uses `approve_files`.
- `get_config() -> ConfigResponse` — returns models, efforts, defaults to frontend for dropdown population.

**Window visibility on new files**: When `watcher.rs` emits `new-files`, `main.rs` calls `window.show()` + `window.set_focus()` to bring the window to the foreground before emitting the event to the frontend. This is the authoritative layer for window visibility — the frontend does NOT call `appWindow.show()` (it only manages UI state like `showConfirmPanel`).

**Tauri plugins** (declared in `tauri.conf.json` and `Cargo.toml`):
- `tauri-plugin-notification` — Windows toast notifications on job completion
- `tauri-plugin-dialog` — native error dialogs for startup validation

**Capabilities** (in `tauri.conf.json`):
- `notification:default` — allow sending notifications
- `dialog:default` — allow native error dialogs

### Frontend (Svelte)

#### `stores/jobs.js` — State Management

```javascript
// Svelte writable stores
jobs: [{
  id: string,           // UUID from Rust (returned by approve_files/start_job)
  filename: string,     // e.g. "06_Machine_Procedures.pdf"
  filepath: string,     // full path
  folder: string,       // parent folder name (e.g. "System Programming")
  outputName: string,   // e.g. "06_Machine_Procedures_Guide.md"
  status: "starting" | "working" | "done" | "failed" | "done-warnings",
  activity: string,     // current activity text (e.g. "Reading: guide_prompt.txt")
  model: string,
  effort: string,
  startedAt: number,    // Date.now() timestamp
  finishedAt: number | null,
  logLines: [{ text: string, tag: string, lineNum: number }],
  // logLines capped at 2000 entries. Oldest evicted when cap exceeded.
  // This bounds memory for long-running jobs while keeping enough history
  // for meaningful scrollback.
}]

selectedJobId: string | null
pendingFiles: string[]     // file paths awaiting approval
showConfirmPanel: boolean
```

#### `lib/parser.js` — JSON Output Parsing (single source of truth)

All Claude stream-json parsing lives here. Both `App.svelte` (for activity updates) and `LogPanel.svelte` (for display) use this module.

```javascript
// parseLine(rawJsonString) -> { text: string, tag: string, activity: string | null }
// tag is one of: "read", "bash", "write", "text", "dim", "error", "header", null
```

Parsing rules:

| Event pattern | Display | Tag |
|--------------|---------|-----|
| `subtype: "tool_use"`, `tool_name: "Read"` | `▸ Read: <filename>` | `read` |
| `subtype: "tool_use"`, `tool_name: "Bash"` | `▸ Bash: <command snippet 55ch>` | `bash` |
| `subtype: "tool_use"`, `tool_name: "Write"` | `▸ Write: <filename>` | `write` |
| `subtype: "tool_use"`, `tool_name: "Edit"` | `▸ Edit: <filename>` | `write` |
| `subtype: "tool_use"`, `tool_name: "Glob"` | `▸ Search: <pattern>` | `read` |
| `subtype: "tool_use"`, `tool_name: "Grep"` | `▸ Grep: <pattern>` | `read` |
| `subtype: "tool_result"` | `✓ <tool> done` | `dim` |
| `subtype: "text"` (text.length > 5) | `▸ Writing: <snippet 80ch>` | `text` |
| `type: "result"` | `Generation complete` | `header` |
| JSON parse failure / non-JSON line | Raw line (truncated 150ch) | `dim` |
| Line containing "error"/"Error" | Error text | `error` |

`activity` is non-null only for `tool_use` events and represents what to show in the sidebar (e.g. "Reading: guide_prompt.txt").

#### `App.svelte` — Root Layout

- CSS grid: sidebar (fixed 240px) + main panel (1fr)
- On mount: listens for Tauri events via `@tauri-apps/api/event`:
  - `new-files` → sets `pendingFiles`, sets `showConfirmPanel = true` (window visibility is handled by Rust backend — frontend only manages UI state)
  - `job-started { job_id }` → updates job status from `"starting"` to `"working"`
  - `job-output { job_id, line }` → calls `parser.parseLine(line)`, appends to job's `logLines`, updates `activity` if parser returns one
  - `job-done { job_id, exit_code, output_file_exists }` → sets `finishedAt`, updates status: exit_code 0 + file exists = `"done"`, non-zero + file exists = `"done-warnings"`, no file = `"failed"`. Sends notification via `tauri-plugin-notification`.
- Elapsed time: `setInterval` every 1000ms updates a reactive `elapsed` map for active jobs

#### `Sidebar.svelte`

- Watching status indicator (green pulsing dot + "Watching")
- "Active" section: jobs with `status === "working"` or `"starting"`
  - Each: filename, folder name, pulsing indigo dot, elapsed time
  - Selected job has highlighted background (gradient blue→purple at 10% opacity)
- "Completed" section: jobs with `status === "done"`, `"done-warnings"`, or `"failed"`
  - Each: filename, green dot (done), yellow dot (warnings), or red dot (failed), final elapsed time
- Click a job → sets `selectedJobId` → LogPanel updates
- When `showConfirmPanel` is true, ConfirmPanel slides in over the sidebar

#### `ConfirmPanel.svelte`

- Slides in from the left over the sidebar (CSS `transform: translateX` + `transition: 300ms ease`)
- Header: "{n} new file(s) detected"
- File list with checkboxes (checked by default)
  - Each: file type badge ([PDF] blue, [HTML] green), filename, folder name
- Model dropdown (populated from `get_config()`, default: opus)
- Effort dropdown (populated from `get_config()`, default: max)
- Buttons: "Generate" (primary, gradient accent), "Skip" (ghost, subtle)
- On Generate → invokes Tauri `approve_files` command with selected paths + model + effort → receives `job_id` array → creates job entries in store → panel slides out → auto-selects first new job
- On Skip → panel slides out, clears `pendingFiles`

#### `LogPanel.svelte`

- Header bar: filename, folder, model/effort tags, elapsed time badge (pill with border)
- Scrollable log area (monospace font, `--font-mono`):
  - Line numbers (dim `--log-line-num`, right-aligned, 3-char width)
  - Color-coded entries per tag from `parser.js`:
    - `read` → `--log-read` (blue)
    - `bash` → `--log-bash` (green)
    - `write` → `--log-write` (purple)
    - `text` → `--log-text` (white 30%)
    - `dim` → `--log-dim`
    - `error` → `--accent-red`
    - `header` → `--accent-purple` bold
  - **Auto-scroll**: scrolls to bottom on new lines. If user scrolls up (scroll position > 50px from bottom), auto-scroll pauses. Resumes when user scrolls back to bottom.
- Empty state when no job selected: centered "Click a job to view its output" in `--text-tertiary`
- **DOM optimization**: only the last 500 lines are rendered in the DOM. Older lines remain in the store's `logLines` array (capped at 2000) and can be scrolled into view via virtual scrolling or on-demand rendering.

#### `StatusBar.svelte`

- Left: pulsing accent dot + current activity text of selected job
- Right: "{n} events" count for selected job's logLines length

## Startup Integration

- Replace current `AutoGuideWatcher.bat` in Windows Startup folder
- New batch file points to the compiled `.exe` directly (no Python/pythonw needed):
  ```bat
  @echo off
  start "" "C:/Users/you/projects\guide-watcher\src-tauri\target\release\guide-watcher.exe"
  ```
- The `.exe` starts hidden in the tray — no console window, no splash

## Migration from Python Version

The Tauri app replaces `guide_watcher_gui.pyw` entirely. Key preserved behaviors:
- Same watch directory, skip folders, skip patterns, batch window, cooldown
- Same Claude CLI invocation method (Git Bash with `--login` flag + heredoc + stream-json)
- Same template file (`guide_prompt.txt`) at the same absolute path
- Same prompt construction logic including per-extension variants (PDF pymupdf extraction, HTML JS template literal regex extraction)
- Same textbook weaving instructions (check for `libgen.li` files in output directory)
- The Python version (`guide_watcher_gui.pyw` and `auto_guide_watcher.py`) remain as fallbacks but are no longer started by the batch files

## Error Handling

| Scenario | Behavior |
|----------|----------|
| `TEMPLATE_FILE` missing at startup | Native error dialog + exit |
| `GIT_BASH` missing at startup | Native error dialog + exit |
| `WATCH_DIR` missing at startup | Native error dialog + exit |
| `GIT_BASH` missing at job start | `job-output` error line + `job-done` with exit_code -1 |
| Temp `.sh` file write fails | `job-output` error line + `job-done` with exit_code -1 |
| Claude process crashes | stdout loop exits, exit code captured, `job-done` emitted |
| File deleted during stability wait | Skipped (file no longer exists after timeout) |
| Watcher thread panics | Logged to stderr, app continues (tray stays alive but watching stops) |
| Notification permission denied | Silently skip notification (non-critical) |
